# Market Advisor Algo Trading Platform Roadmap

This document turns the current NSE stock alert and recommendation app into a full algo trading platform in controlled phases. It is written for this repo's current shape: Next.js frontend in `web/`, FastAPI backend in `api/`, Supabase/Postgres migrations in `supabase/`, Redis support, and existing recommendation/backtest modules.

## Product North Star

Build an India-first algo trading platform where users can design, test, paper trade, and deploy strategies across equities, futures, and options with strong risk controls and auditability.

Primary competitors to benchmark:

- Tradetron/Streak: no-code strategy creation and broker deployment.
- AlgoTest/Quantman: options backtesting, metrics, and optimization.
- TradingView: charting, alerts, watchlists, and polished real-time UX.

## Current Baseline

Already present:

- Supabase auth and role-aware dashboard.
- NSE stock scanning and recommendations.
- Watchlists, signals, portfolio workspace, admin tools, chatbot advisor.
- Basic historical simulator in `api/app/services/backtester.py`.
- Backtest storage tables in `supabase/migrations/007_backtest_runs.sql`.

Current gaps:

- No canonical strategy model. Recommendations are generated by backend rules, but users cannot compose strategies.
- Backtesting is scan-based, not event-driven or order-aware.
- No order lifecycle, broker adapters, paper ledger, positions, fills, or risk engine.
- Historical data source is `yfinance`, which is not enough for serious 1-minute/options testing.
- RLS policies are permissive in several existing migrations and must be tightened before marketplace/live trading.

## Target Architecture

Keep the monorepo, but separate finance domains cleanly.

```text
web/
  src/app/
    strategies/          Strategy builder, versions, deployments
    backtests/           Backtest lab, reports, comparison
    paper/               Paper trading terminal
    live/                Live algo dashboard
    marketplace/         Published strategies and subscriptions
    brokers/             Broker connections

api/
  app/
    domains/
      strategies/        Strategy DSL, validation, versioning
      marketdata/        Candles, instruments, options chain
      backtesting/       Event-driven engine, costs, reports
      execution/         Orders, positions, broker adapters
      risk/              Limits, kill switch, drawdown protection
      marketplace/       Publishing, subscriptions, verification
      notifications/     Email, WhatsApp, Telegram, push
      audit/             Immutable logs, compliance exports
    workers/             Redis-backed background jobs
    realtime/            WebSocket/SSE streams

supabase/
  migrations/            Canonical schema and RLS
```

Use FastAPI for finance-critical backend logic. Keep Next.js/Vercel for frontend. Run long jobs and live execution workers outside Vercel serverless, because broker sessions, websockets, and backtests need durable processes.

## Core Data Model

Add these Postgres domains incrementally.

### Instruments And Market Data

- `instruments`: NSE/BSE symbol, exchange token, segment, lot size, tick size, expiry, strike, option type.
- `candles`: instrument id, timeframe, open/high/low/close/volume/open interest, timestamp.
- `ticks` or `ltp_snapshots`: real-time price snapshots for paper/live execution.
- `options_chain_snapshots`: expiry, strikes, bid/ask, IV, Greeks, OI, change in OI.

Partition candles by date/timeframe once volume grows.

### Strategies

- `strategies`: owner, name, description, visibility, status.
- `strategy_versions`: immutable JSON DSL, semantic version, created by, checksum, validation status.
- `strategy_blocks`: optional normalized block storage for UI editing/search.
- `strategy_deployments`: version, broker/paper/live mode, capital, risk profile, state.
- `strategy_signals`: generated entry/exit intents from a version.

Canonical strategy DSL shape:

```json
{
  "meta": { "name": "RSI EMA Pullback", "market": "NSE", "timeframe": "5m" },
  "universe": { "type": "watchlist", "symbols": ["RELIANCE", "TCS"] },
  "entry": {
    "all": [
      { "indicator": "rsi", "period": 14, "operator": "<", "value": 35 },
      { "crosses": { "left": "ema_9", "right": "ema_21", "direction": "above" } }
    ]
  },
  "exit": {
    "any": [
      { "target_pct": 2.0 },
      { "stop_loss_pct": 1.0 },
      { "trailing_stop_pct": 0.8 }
    ]
  },
  "position": { "sizing": "fixed_risk", "risk_per_trade_pct": 1.0 },
  "reentry": { "enabled": true, "max_count": 2, "cooldown_candles": 3 }
}
```

### Backtesting

- `backtest_jobs`: requested strategy version, date range, symbols, timeframe, status.
- `backtest_reports`: summary metrics, equity curve, drawdown curve, settings snapshot.
- `backtest_trades`: orders/fills/trades with costs and slippage.
- `backtest_daily_stats`: day-wise P&L, exposure, max drawdown.
- `optimization_runs`: grid/walk-forward/Monte Carlo config and results.

Do not extend the current scan simulator into the final engine. Keep it as legacy quick validation while building an event-driven engine.

### Trading And Execution

- `broker_accounts`: user, broker, masked client id, token metadata, status.
- `orders`: normalized order intent and broker order id.
- `fills`: executed quantity/price/time/costs.
- `positions`: live and paper positions.
- `execution_events`: every state transition from signal to order to fill.
- `risk_limits`: per user/deployment limits.
- `kill_switch_events`: manual/automatic shutdowns.

### Marketplace

- `strategy_publications`: strategy version, listing copy, pricing, risk category.
- `strategy_subscriptions`: buyer, seller, status, renewal, broker auto-follow settings.
- `strategy_performance_verifications`: independently computed performance stats.
- `seller_payouts`: commission and settlement records.

## Backend Milestones

### Phase 1: Strategy Foundation

Goal: user can create, clone, version, and validate a strategy, without execution.

Backend:

- Add `domains/strategies` with Pydantic models for strategy DSL.
- Add validation endpoint: `POST /api/strategies/validate`.
- Add CRUD endpoints:
  - `GET /api/strategies`
  - `POST /api/strategies`
  - `GET /api/strategies/{id}`
  - `POST /api/strategies/{id}/versions`
  - `POST /api/strategies/{id}/clone`
- Add Supabase migrations for strategies and versions.
- Add strict owner-based RLS.

Frontend:

- Add `/strategies`.
- Start with form/condition builder before drag-and-drop.
- Support price, time, RSI, EMA, SMA, MACD, Supertrend, Bollinger, volume, candle patterns.
- Add JSON preview for power users.

### Phase 2: Serious Backtesting MVP

Goal: event-driven backtest for one strategy version over historical candles.

Backend:

- Add candle ingestion abstraction with provider interface.
- Add brokerage model for Indian equities/F&O:
  - brokerage cap/percent,
  - STT/CTT,
  - exchange transaction charges,
  - SEBI charges,
  - stamp duty,
  - GST,
  - slippage model.
- Add event loop:
  - candle in,
  - indicators update,
  - signal evaluate,
  - order simulate,
  - fill,
  - position update,
  - risk update.
- Metrics:
  - net P&L,
  - CAGR,
  - max drawdown,
  - Sharpe/Sortino,
  - win rate,
  - profit factor,
  - expectancy,
  - average win/loss,
  - exposure,
  - drawdown duration.

Frontend:

- Add `/backtests`.
- Report cards, equity curve, drawdown curve, trade list, day heatmap.
- Compare two or more reports.

### Phase 3: Paper Trading

Goal: run strategies live against market feed using virtual capital.

Backend:

- Add deployment state machine: `draft -> active -> paused -> stopped -> failed`.
- Add paper broker adapter implementing same interface as live brokers.
- Add real-time position/P&L streams via SSE first, WebSockets later if needed.
- Add risk engine:
  - max loss per day,
  - max open positions,
  - max order value,
  - max strategy drawdown,
  - no-trade windows,
  - kill switch.

Frontend:

- Add `/paper`.
- Running algos table, virtual positions, order book, trade book, P&L chart.

### Phase 4: Broker Integrations

Goal: safe live trading through one broker, then expand.

Adapter interface:

```python
class BrokerAdapter:
    def place_order(self, order): ...
    def modify_order(self, broker_order_id, patch): ...
    def cancel_order(self, broker_order_id): ...
    def get_order(self, broker_order_id): ...
    def get_positions(self): ...
    def get_margin(self): ...
    def subscribe_ticks(self, instruments): ...
```

Integration order:

1. Zerodha Kite Connect.
2. Upstox.
3. Angel One SmartAPI.
4. Alice Blue.
5. 5Paisa.

Hard rules:

- Never place a live order without deployment-level risk limits.
- Store encrypted broker tokens only.
- Require explicit user confirmation before first live deployment.
- Add static IP support for brokers that require whitelisting.
- Add complete audit logs.

### Phase 5: Options Platform

Goal: India-first F&O strategy support.

Features:

- Options chain with OI, IV, Greeks, PCR, max pain.
- Strategy templates:
  - long/short straddle,
  - long/short strangle,
  - iron condor,
  - iron butterfly,
  - bull/bear spreads,
  - covered call/protective put.
- Multi-leg order simulation and execution.
- Margin estimates.
- Expiry handling.
- Leg-level stop loss/target and strategy-level exit.

### Phase 6: Marketplace

Goal: verified strategy marketplace.

Features:

- Publish immutable strategy version.
- Seller profile and subscription pricing.
- Verified performance from platform-generated backtests/live paper/live stats.
- Auto-follow/copy trading with buyer risk caps.
- Rankings based on risk-adjusted metrics, not raw return.
- Abuse controls: no fake screenshots, no editable performance claims.

## Frontend Design Direction

Dark-mode-first, dense, premium trading UI.

Key surfaces:

- Left navigation: Dashboard, Strategies, Backtests, Paper, Live, Marketplace, Brokers, Admin.
- Strategy builder:
  - toolbar for indicators/conditions/actions,
  - central canvas or grouped rule panels,
  - right inspector,
  - bottom validation/errors panel.
- Charts:
  - TradingView Lightweight Charts,
  - overlays for entries/exits/SL/target,
  - synced trade list.
- Dashboards:
  - cards only for individual metrics/items,
  - tables for operational workflows,

  - heatmaps for calendar and sector/options exposure.

## Market Data Strategy

Use `yfinance` only for prototype scans.

Production-grade needs:

- Historical 1-minute candles for equities/F&O, 5-10 years where available.
- Corporate-action-adjusted data.
- Survivorship-bias-aware symbol universe.
- Options historical chain data with OI/IV/Greeks.
- Real-time feed for live/paper.

Provider candidates:

- Broker feeds for real-time execution.
- Dedicated Indian market data vendors for historical intraday and options.
- Internal candle store in Postgres/Timescale-compatible storage or ClickHouse later.

## Compliance And Safety

SEBI-ready posture:

- Clear "educational/tools" vs "investment advice" boundaries until registered.
- Audit every recommendation, signal, strategy change, deployment, order intent, broker response, and risk decision.
- Immutable strategy versions used for live trading.
- Explicit user consent before enabling auto-trading.
- Kill switch at user, strategy, broker, and platform levels.
- No guaranteed return language.
- Marketplace performance must be computed by platform, not seller-entered.
- Encrypt broker credentials and tokens.
- Tight RLS: users can only see their own private data; public marketplace data is separate.

## Implementation Principles

- Treat strategy versions as immutable.
- Use same execution contract for backtest, paper, and live.
- Keep broker-specific quirks inside adapters.
- Compute performance server-side only.
- Prefer one reliable broker integration over many shallow integrations.
- Add live trading last, after paper trading and risk controls prove stable.
